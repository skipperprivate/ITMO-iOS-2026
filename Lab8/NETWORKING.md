# Сеть в MiniTwitter

Приложение использует `https://test.play-trace.com` без авторизации.

## Запросы

- `GET /api/posts?page=1&pageSize=25` возвращает `page`, `pageSize`, `total`, `items`.
  Запрос выполняется при открытии ленты, обновлении жестом вниз и загрузке следующей страницы.
- `POST /api/posts/{id}/like` отправляется без тела. Проверенный ответ:
  `{"postId":"cc2cd60c-4689-4c3c-985f-a5f46c38389a","likes":3}`.
  Он добавляет лайк; снятие лайка опубликованным API не предусмотрено.

В `TwitterAPIClient` запросы выполняются через `URLSession.data(for:)` и `async/await`.
Проверяются HTTP-статус, соответствие страницы и идентификатора ответа POST запросу.
`JSONDecoder` преобразует JSON в `PostsPage`, `RemotePost` и `LikeResponse`.
Обрабатываются ISO 8601 даты как с дробными секундами, так и без них, а также `null`
в имени автора. Неиспользуемые поля ответа, например `photos`, не отображаются.

## Кэш и пользовательские действия

Сначала показываются данные SwiftData, затем выполняется GET. Репозиторий объединяет
ответ с кэшем по `serverID`, сохраняя локальный UUID, избранное и отметку лайка.
Старые записи кэша не удаляются при загрузке одной страницы. Поэтому фильтр
«Избранное» работает для всех уже сохранённых на устройстве записей, в том числе офлайн.

Локальные твиты по-прежнему можно создавать, редактировать и удалять. У них нет
`serverID`, и для них недоступен серверный лайк. Серверные твиты доступны для чтения,
лайка и добавления в избранное. Редактирование и удаление таких записей блокируются
также на уровне репозитория.

Сердце отправляет POST и показывает подтверждённый сервером счётчик. После успеха
`isLiked` сохраняется локально и повторная отправка с этого устройства блокируется.
Это локальная отметка: API не идентифицирует пользователя, поэтому переустановка
или другое устройство не имеют общей истории его лайков.

Закладка меняет `isFavorite` только в SwiftData. Она не вызывает POST и не влияет
на счётчик лайков. Обновление с сервера не сбрасывает закладку.

В UserDefaults используются два ключа:

- `tweetsCacheLastUpdate` — последняя успешная запись в локальный кэш;
- `tweetsLastServerSync` — последняя успешная загрузка и сохранение страницы GET.

Новые поля SwiftData имеют значения по умолчанию или являются optional.
Проверена миграция базы с прежней схемой без удаления старых твитов.

## Ошибки

Обрабатываются отсутствие интернета, потеря соединения, тайм-аут, HTTP-ошибки,
неправильный JSON, неверные даты и некорректные ответы. При ошибке GET остаётся кэш
и появляется кнопка повтора. Отмена не показывается как ошибка.

POST не повторяется автоматически. Если соединение прервалось после приёма запроса
сервером, приложение не может достоверно определить результат: API не предоставляет
ключ идемпотентности или историю лайков пользователя. Сообщение предлагает обновить
ленту перед ручной повторной попыткой. Счётчик не увеличивается предположительно.

## Проверки

```sh
bash Tests/run-concurrency-checks.sh
```

Тесты используют `URLProtocol` с подменёнными ответами и временную базу. Они проверяют
миграцию, парсинг, GET/POST, сетевые ошибки, отмену, пагинацию без дубликатов, лайк,
избранное, read-only ограничения, локальный CRUD, конкурентные записи и сохранение
данных между отдельными процессами. Они не изменяют данные реального сервера.

```sh
bash Tests/run-concurrency-checks.sh --live
```

Флаг `--live` дополнительно выполняет настоящий GET и проверяет парсинг ответа.
Реальный POST был проверен отдельно при реализации: счётчик тестового поста вырос
с 2 до 3. Повторные автоматические POST-проверки используют подменённый сервер.

Для защиты: показать загрузку и обновление ленты, сердце и счётчик, локальную
закладку и фильтр, затем отключить сеть и продемонстрировать кэш и сообщение об ошибке.
