# Лабораторная работа № 7
## Unit and UI testing with XCTest and XCUITest

### Цель работы
Освоить модульное и пользовательское тестирование iOS-приложения средствами XCTest и XCUITest.

### Реализация
В проекте Weatherly используются два отдельных тестовых target:
- `WeatherlyTests` — модульные тесты доменных моделей, преобразования единиц измерения, сериализации настроек, ViewModel, репозиториев и сетевого слоя. Для изоляции сетевых сценариев применяются тестовые реализации репозиториев и URLProtocol-заглушка.
- `WeatherlyUITests` — UI-тесты запуска приложения, перехода в настройки, открытия списка городов и ввода текста в поиск.

Для стабильной автоматизации добавлены accessibility identifiers: `home.settings`, `home.places`, `home.findCity`, `places.search`. Они отделяют идентификацию элементов тестами от их отображаемого текста и дизайна.

### Запуск
1. Открыть `Weatherly.xcodeproj` в Xcode.
2. Выбрать схему `Weatherly` и iOS Simulator.
3. Запустить все тесты сочетанием `Cmd + U`.
4. Для запуска только модульных или UI-тестов выбрать соответствующий test target в Test Navigator.

### Проверяемые сценарии
**Unit tests:** преобразование температуры, скорости ветра и давления; значения настроек по умолчанию; кодирование/декодирование настроек; обработка неизвестных значений; часовой пояс и подзаголовок города. Дополнительно в проекте уже присутствуют тесты ViewModel, сетевых запросов, маппинга API-ответов, репозиториев и ограничения параллелизма.

**UI tests:** приложение запускается; пользователь открывает экран настроек и видит группы параметров; пользователь открывает экран мест и видит поле поиска; поле поиска принимает ввод.

### Ожидаемый результат
Тесты выполняются в Xcode на симуляторе. Unit-тесты проверяют отдельные компоненты без реального обращения к Open-Meteo, UI-тесты проверяют ключевые пользовательские действия через интерфейс приложения.
