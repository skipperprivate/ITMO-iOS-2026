# Лабораторная работа №7 — тестирование MenuPlanner

В `Project/MenuPlanner/MenuPlanner.xcodeproj` добавлены два отдельных тестовых таргета:

- `MenuPlannerTests` — 109 unit-тестов на XCTest с `@testable import MenuPlanner`.
- `MenuPlannerUITests` — 18 UI-тестов на XCUITest, запускающих настоящее приложение.

Оба таргета подключены к общей схеме `MenuPlanner`, для которой включён сбор покрытия кода.
Минимальная версия iOS для тестов совпадает с приложением: 18.6.

## Unit-тесты

- `ShoppingListBuilderTests`: масштабирование порций, объединение одинаковых ингредиентов после нормализации, разделение несовместимых единиц, пустое меню и некорректные порции.
- `RecipesViewModelTests`: поиск по названию и ингредиентам, совместная работа фильтров, избранное и стабильная сортировка.
- `RecipeEditorTests` и `RecipeEditorAdvancedTests`: валидация формы и чисел, импортированные товарные подсказки, создание и редактирование рецептов, повторное использование ингредиентов и удаление старых строк.
- `WeekPlanTests`: границы недели, добавление/изменение/удаление блюда, пересборка покупок с сохранением отметок, обработка ошибочного меню, отметка «есть дома», удаление рецепта и связанных записей меню.
- `UserSettingsTests`: начальное состояние, сохранение онбординга и профиля, очистка даты рождения.
- `RecipeImportMapperTests`: время приготовления, дробные количества, неизвестные единицы, порядок шагов и проверка ссылок источника.

- `VkusVillProductTests`: масса/объём/штуки, десятичная запятая, округление упаковок, пределы количества, неподходящие единицы и метаданные товаров.
- `VkusVillCatalogTests`: HTTP-запросы и MCP handshake, JSON/SSE, дубликаты и неверные ID, сетевые и серверные ошибки, повреждённые ответы, ограничения корзины, ссылки и размер/MIME фотографий.
- `RecipeImportViewModelTests`: пустой/длинный запрос, замена результатов, пагинация без дублей, ошибки следующих страниц, повтор и отмена.
- `VkusVillSearchViewModelTests`: состояния поиска, пустые результаты, повтор, отмена старого запроса, загрузка первых трёх подсказок с пропуском ошибок.
- `VkusVillCartViewModelTests`: группировка, исключение купленных/домашних продуктов, пропуск/возврат/замена товара, суммирование одного SKU, лимиты 40/100, дробные количества, повтор, отмена, запрет повторной отправки и сброс устаревшей ссылки.
- `PersistenceAndFormattingTests`: склонения, избранное и обновление карточки, очистка встроенных примеров, раздельные списки недель, метаданные товаров, границы месяца/года/високосного февраля.
- `PersistenceFailureTests`: настоящая SQLite-база, открытая только для чтения; проверяются отказ сохранения, сохранность рецепта/меню/покупок/избранного на диске и сообщения об ошибках; известный дефект отката в памяти отмечен отдельно.

Обычные SwiftData-тесты создают отдельный `ModelContainer` в памяти; проверки сохранения читают данные через новый `ModelContext`. Тесты настроек используют отдельные UserDefaults suites и удаляют их после выполнения.

18. Пропуск товара в корзине, возврат к подбору и сохранение привязки товара.

UI-тесты работают без реальной сети и без предзаполненной пользовательской базы: рецепты и меню создаются через интерфейс. `UITestNetwork.swift` перехватывает HTTP-запросы каталога через URLProtocol только в Debug при `--ui-testing`. Он возвращает фиксированные ответы сервиса; фотографии в них отсутствуют, чтобы AsyncImage не обращался в интернет.
В unit-тестах используется отдельная URLSession с URLProtocol; проверяется реальный код клиента, сериализация запросов и разбор ответов.
`MENU_PLANNER_NETWORK_SCENARIO=retry` заставляет первый вызов каждого инструмента/запроса завершиться HTTP 503, следующий — успешно; `offline` возвращает HTTP 503 постоянно.
В Debug аргумент `--ui-testing` включает SwiftData в памяти, отдельные UserDefaults по `MENU_PLANNER_TEST_ID` и отключает UIKit/SwiftUI-анимации для устойчивого XCUITest.
Параметр `--skip-onboarding` открывает основной экран. При перезапуске в рамках одного теста настройки сохраняются, а рецепты и меню в памяти очищаются. Release-сборка не обрабатывает тестовые аргументы.

## Запуск

В Xcode: открыть проект, выбрать схему `MenuPlanner` и iPhone Simulator, нажать **⌘U**.
В Test Navigator можно запустить каждый таргет или отдельный тест.

Из корня репозитория:

```sh
xcodebuild test \
  -project Project/MenuPlanner/MenuPlanner.xcodeproj \
  -scheme MenuPlanner \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -parallel-testing-enabled NO
```

Для одного набора добавить `-only-testing:MenuPlannerTests` или `-only-testing:MenuPlannerUITests`.
Название симулятора можно заменить на любое доступное с iOS 18.6 или новее.
Покрытие доступно в Xcode: Report Navigator → последний Test → Coverage.

## Обнаруженный дефект SwiftData

На iOS 26.5 после отказа записи в read-only SQLite `ModelContext.rollback()` оставляет изменения в памяти: вставленный рецепт, удалённую запись, порции, отметки покупок, избранное или товарную привязку. Новый ModelContext читает исходные данные с диска — постоянное хранилище не повреждается. Поведение воспроизведено вне приложения на минимальной модели.

Семь тестов `PersistenceFailureTests` содержат строгий `XCTExpectFailure` **только для проверок отката в памяти и только на iOS 26.5**. Это известные сбои, а не подтверждение корректного отката. Проверки отказа, сообщений и сохранности данных на диске остаются обычными assertions. Неожиданное восстановление отката на этой версии также сделает тест красным и потребует убрать отметку; на других версиях ОС проверка выполняется без исключения.

[Документация Apple для rollback](https://developer.apple.com/documentation/swiftdata/modelcontext/rollback%28%29) описывает восстановление последнего зафиксированного состояния. Исправление обхода этого поведения в слое хранения не входит в изменения тестового набора.

## Границы проверки

Процент покрытия строк показывает исполнение кода, а не полноту всех возможных состояний.
Ошибки записи проверяются на read-only SQLite, сетевые ошибки — на управляемых HTTP-ответах.
Живая доступность API ВкусВилла, реальные заказы, системный выбор фото/разрешения, VoiceOver и визуальная адаптация на всех моделях устройств этим набором не проверяются.
